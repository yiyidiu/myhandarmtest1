# P0 remediation 04: perception timing and measurement provenance

本阶段修复正式真人录像中 `4.5408 Hz`、29.1% 测量间隔超过 `250 ms` 的视觉时序
故障，并补齐相机帧到 ROS 的测量来源与延迟契约。结论只覆盖固定 ROI 时序、异步前臂
锚点和 C 令牌失效安全；它不代表真人检测、手指重定向或端到端遥操作已经合格。

## 根因

`scheduler_rate_hz: 5.0` 并未在实时入口中生效，低频不是人为限频。RTX 2070 上修改前
的纯 HaMeR 已能达到 `21.945 Hz`，而原实时循环还在每次 HaMeR 后同步执行 RGB-D
前臂拟合（历史真人帧约 `34--87 ms`）、冻结形状后的第二次 MANO 求值，以及控制发布前
的完整网格渲染。显示、记录和控制时序也共用同一主循环，导致计算串行叠加和长尾间隔。

## 实现

- RGB-D 前臂拟合改为容量 1、旧任务覆盖、默认最高 8 Hz 的异步 worker。任务拥有深度
  副本，并绑定 presence generation、active-hand generation、handedness 和上下文代次；
  过期、换手或重捕获结果绝不融合，失败时精确回退到 MANO。
- 实时显示的完整 MANO 网格渲染移出控制发布路径，由显示线程按精确推理帧缓存渲染；
  只有显式实验录像仍同步生成逐帧证据。
- 冻结用户 betas 后，在单次 HaMeR forward 内、MANO 求值前注入形状，移除每帧第二次
  MANO 调用。实模型逐元素对比中 vertices、3-D joints、camera 和投影 2-D 结果误差均为 0。
- 实时循环不再无限保留包含 MANO 全网格的所有帧记录；非实验模式只保留紧凑时序统计。
- 每个 UDP 包记录 capture sequence、覆盖丢帧数、采集到发布、推理调用、模型推理和
  后处理时间。ROS 消息与同步 CSV 原样保留这些字段；有效实时包缺少时序契约或
  `capture_to_publish > 0.20 s` 时 fail closed。
- UDP 断流 `0.40 s` 后锁定当前 C 令牌；同一令牌恢复发送仍不能恢复控制，必须出现新的
  C epoch。适配器自身的启动看门狗状态不再冒充相机窗口真实的“尚未按 C”状态。
- 相机模型使用显式白名单，当前 D435i 与原 D455 共用已审核的 640x480@30 对齐 RGB-D
  契约；未审核 RealSense 型号仍拒绝启动。

## 性能验收

### 纯 HaMeR，固定 batch 1

| 指标 | 修改前 | 修改后 |
|---|---:|---:|
| 吞吐率 | 21.945 Hz | 24.278 Hz |
| 平均推理调用 | 45.568 ms | 41.190 ms |
| P95 推理调用 | 48.712 ms | 42.854 ms |

### 实际 D435i 完整采集链，固定 ROI、12.05 s

设备为 RealSense D435i（USB 3.2，640x480@30），GPU 为 RTX 2070。241/241 个
处理样本产生 pose packet：

| 指标 | 结果 |
|---|---:|
| 有效 pose packet 频率 | 20.000 Hz |
| 帧间隔 mean / P95 / max | 49.78 / 53.51 / 66.17 ms |
| 帧间隔超过 250 ms | 0% |
| 模型推理 mean / P95 | 43.16 / 46.57 ms |
| 完整推理调用 mean / P95 | 45.45 / 49.18 ms |
| 采集到发布 mean / P95 / max | 70.96 / 87.22 / 94.02 ms |
| 后处理 mean / P95 | 4.37 / 7.76 ms |

30 Hz 相机在 20 Hz 推理消费者前覆盖了 118 个旧帧；这是容量 1 的主动丢旧策略，
不存在推理队列积压。该试验使用未经过真人 presence 验证的固定 ROI，只能用于时序，
不能用于判断跟踪正确性或空间误差。

### 真实历史 RGB-D 前臂帧异步回放

把正式 D435i 真人帧以 20 Hz 连续提交给 8 Hz 前臂 worker：40 个输入中完成 17 个、
覆盖 23 个旧任务、0 error；主线程提交耗时 mean/P95/max 为
`0.256/0.393/0.522 ms`。最新结果可用，源帧年龄 `68.62 ms`，worker 计算
`15.20 ms`。这证明可选前臂锚点不再把其计算时间串入 HaMeR 发布周期。

## C 令牌 Gazebo 验收

无 GUI 验证依次执行：接收器启动前旧 C、按新 C、运动、UDP 静默 1.0 s、恢复相同
C、再次按新 C、运动和回零。最终结果为 PASS：

- 启动前旧 C 最大工具位移 `0.0079 mm`；
- 超时后同一 C 最大工具位移 `0.0000 mm`；
- 新 C 前后两次 25 mm 图像向右输入分别产生 `-14.863/-14.886 mm` 的 base-Y 位移；
- 最终回零误差 `0.110 mm`；Servo 危险状态为空。

第一次运行该新验收时发现适配器启动看门狗被误认成相机 C-up 证据，旧令牌造成
`149.1 mm` 运动。现在只有携带生产者时序契约的真实相机禁用包能满足启动边沿，修复后
同一试验通过。该失败过程被保留在记录中，因为它说明仅有 token 字段而没有消息来源
语义仍不足以构成安全状态机。

## 仍未完成

- 尚未在真人手、自动 MediaPipe presence、显示窗口、UDP、Gazebo 和同步录屏同时运行
  的 C-to-Q 试验中复验 20 Hz 与 P95 端到端延迟。
- 固定 ROI 基准不评价手腕位置/姿态准确度、遮挡、快速运动、handedness 或重捕获。
- 人手手指仍没有到三指机械手的运动学重定向；当前稳定手 plant 只证明固定目标时不再
  随机械臂剧烈振荡。
- 因此端到端“不合格”结论仍有效。下一阶段应实现并离线验收手指 retargeting，再按
  用户规定的 C-to-Q 流程重新录制同步视频和全部数据。
