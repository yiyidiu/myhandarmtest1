# P0 remediation 05: continuous finger retargeting

本阶段修复正式录像中“人手五指在动，但四个机械手主动目标全程恒定”的缺失链路。
结论覆盖连续 MANO 手指观测、C 后张手标定、低维五到三指映射、Gazebo 执行、同步
日志和失效锁定；尚不等于真人闭合动作或接触抓取已经通过端到端验收。

## 根因

- 相机实时包把 `gesture` 和 `gesture_confidence` 固定为 0，没有发送连续手指状态。
- `HamerHandPose`/`HandCommand` 只有腕部六维量和离散手势占位字段。
- `mock_three_finger_hand_adapter.py` 只打印手势字符串，从不发送机械手关节命令。
- 因此旧录像中的机械手手指运动只能来自旧 Gazebo plant 的被动振荡，不是遥操作。

## 人手观测与映射

HaMeR 的 21 个关节点采用 OpenPose 顺序：手腕，随后拇指、食指、中指、无名指和小指
各四点。本实现对每条“手腕—指尖”链累计三个内部弯曲角并除以 π，得到五维连续特征。
角度特征对相机平移、整体旋转和手尺度不变；MANO_RIGHT 的关节旋转轴没有被错误地
当作机器人关节轴使用。

新的 UDP 嵌套契约携带：

- 明确的 feature definition/version；
- `[thumb,index,middle,ring,pinky]` 五维弯曲量；
- 有效位、置信度和精确失效原因。

ROS 侧保留机器人无关的人手量，再执行显式的三指协同映射：

| 机器人主动屈曲关节 | 人手来源 |
|---|---|
| `f1j2` | 食指 |
| `f2j1` | 拇指（对置指） |
| `f3j2` | 中指/无名指/小指按 0.5/0.3/0.2 合成 |

`f1j1` 是掌面/外指配置，不随人手瞬时变化，固定在已完成碰撞和抓取几何审核的
`0.18 rad`。三个屈曲目标只在审核的 OPEN→CLOSE 区间内变化：
`f1j2/f2j1 0.20--0.85 rad`、`f3j2 0.20--0.90 rad`。

这是一种适合当前欠驱动三指手的形态归一化 synergy retargeter，而不是五指灵巧手的
完整指尖任务空间优化。后续若要评价精细捏取、接触点保持或物体内操作，仍应增加带
机器人正运动学、自碰撞和接触目标的优化层。

## 因果与失效安全

- 每个新 C token 必须先得到连续 4 帧稳定且张开的手型，中位数才成为该操作者/该
  identity 的基线；弯曲或移动中的 C 参考不会解锁机械手。
- 使用 One Euro 因果滤波平衡静止抖动和主动运动延迟；历史张手平移数据测得的模型
  姿态漂移由实测死区隔离。
- 单帧弯曲创新最多 0.25。孤立尖峰保持并拒绝；连续 3 帧一致的新手型被确认后接收，
  避免第一次实现中“合法快速张手被永久拒绝”的状态机死锁。
- 命令步长按 0.06 s 轨迹和 `0.40/0.75/0.75/0.75 rad/s` 限制；所有目标再次受 URDF
  限位约束。
- 低置信度、无效手指、无效腕姿、陈旧关节状态或异常输入立即发布实测当前位置保持。
  连续 `0.45 s` 没有有效手指观测会锁定当前 C；持续 INVALID 心跳不能伪装成有效输入。
  同一旧 C 恢复后仍不能运动，必须产生新 epoch。

## 历史真人张手回放

三组 D435i/HaMeR 真人记录包含完整 21 点 MANO 数据，动作范围是静止张手或张手平移，
不是闭拳试验。回放按 `0.45 s` 缺口切段并为每段建立新 C，结果：

| 会话 | 有效帧 | 连续段 | 四个机器人目标最大峰峰值 |
|---|---:|---:|---:|
| `DEV_HAMER_STATIC_20260826T174752` | 114 | 1 | `0.0000 rad` |
| `DEV_HAMER_TRANSLATION_20260826T174330` | 118 | 2 | `0.0000 rad` |
| `DEV_HAMER_TRANSLATION_20260826T174857` | 140 | 1 | `0.0000 rad` |

这项试验证明张手的刚体平移不会再被解释为机械手闭合。可复现入口为
`validate_finger_open_hand_replay.py`；它不证明真人闭拳的幅值、延迟或指间独立性。

## UDP→ROS→Gazebo 验收

`./scripts/run_finger_retargeting_gazebo_validation.sh` 从严格 UDP 包开始，经过消息契约、
C token、重定向节点和真实 finite-compliance Gazebo hand plugin，最终从 `/joint_states`
测量。增加动臂阶段后的完整运行 PASS：

- 张手目标实测为 `[0.18000, 0.20000, 0.20000, 0.20000] rad`；
- 仅弯食指：`f1j2 +0.65001 rad`，其余屈曲关节串扰最大 `0.00001 rad`；
- 仅弯拇指：`f2j1 +0.65000 rad`，串扰最大 `0.00002 rad`；
- 中/无名/小指协同：`f3j2 +0.70000 rad`，串扰最大 `0.00001 rad`；
- 四次重新张手的最大关节误差均低于 `0.00007 rad`；
- 连续 INVALID 后看到了 `FINGER_INPUT_TIMEOUT_REQUIRES_NEW_C`；同一旧 token 的最大
  关节变化低于 `0.00010 rad`，新 C 后食指响应重新达到 `+0.65002 rad`。

同一次验收保持人手五维特征完全不变，同时用腕部 UDP 让机械臂运动。臂关节实际峰峰
值最大 `0.20285 rad`；四个主动手关节位置峰峰值分别为
`0.00111/0.00345/0.00277/0.00204 rad`，速度 P95 分别为
`0.01289/0.02895/0.02337/0.01721 rad/s`。这直接覆盖旧录像中“机械臂一动，固定手指
剧烈抖动”的故障模式，并满足 `0.01 rad / 0.20 rad/s` 门槛。

第一次端到端运行没有通过：验证器从全闭一帧跳回全开，旧创新门拒绝后未推进比较
基准，造成后续合法恢复永久被拒绝。该失败促成上述“三帧一致创新确认”，随后运行
以及增加动臂阶段后的运行均通过；没有把失败结果重新解释为成功。

## 同步证据与自动化

- `HamerHandPose.msg` 和 CSV 新增人手五维量、置信度、失效原因、归一化机器人闭合量、
  期望/已发/实测四关节量和重定向状态。
- 观测几何、UDP 契约、标定、映射、限幅、创新确认和令牌锁定均有纯 Python 测试。
- ROS 消息重新生成和完整 catkin 编译通过；感知侧 `214/214`、catkin 工作区 `122/122` 测试通过。

## 尚未完成

- 第一次正式屏幕录像只保存了画面、旧腕部消息和恒定机械手目标，没有保存逐帧 21 点
  MANO 关节，因此不能从那段数据严谨地反算真人每根手指的期望关节量。录像仍用于证明
  “旧链路不存在”和观察故障，数值回放使用另存的真人 HaMeR 原始帧。
- 目前没有真人张合序列的同步数值证据；闭合独立性和幅值只通过契约级合成特征与真实
  Gazebo plant 验收。
- 尚未重跑用户规定的相机窗口 C→真人动作→Q 同步视频/ROS/CSV 流程。因此整个系统
  仍不能标记为“真人遥操作合格”；下一步必须用真实五指张合、腕部运动和遮挡恢复共同
  复验，并根据数据调整死区/协同权重，而不是只凭视觉观感调参。
