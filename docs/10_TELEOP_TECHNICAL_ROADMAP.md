# 10 人手遥操作机械臂-三指手系统技术路线

日期：2026-08-14
范围：D455 深度相机 -> 人手位置/姿态估计 -> 坐标映射 -> 机械臂末端（ABB IRB120, tool0）位置/姿态跟随 -> 手势控制三指手开/合/构型 -> 先仿真后实体 -> 任务泛化
依据：本工作区已审计的实测现状（docs/00_CURRENT_SYSTEM_AUDIT.md、docs/SIM_00..03_*.md、docs/P3_P4_HAMER_PALM_STABILITY.md、docs/P5_RGBD_RELATIVE_ORIENTATION.md、docs/REVIEW_DECISIONS.md）。本文所有“已证实/未证实”的措辞均沿用这些文档的证据口径，不把静态配置当作运行能力。

## 1. 目标定义与“泛化”的含义

### 1.1 目标

1. **位姿跟随**：D455 实时估计人手掌（或手腕+掌）的 6-DoF 位姿（位置 + 姿态），经坐标映射后控制仿真中 ABB IRB120 的末端 tool0 跟随人手运动。
2. **手势控制**：人手手势映射为三指手命令（张开 / 自适应抓握 / 构型变换 / 停止），与 6-DoF 跟随通道解耦。
3. **任务完成**：通过“人手遥操作 + 手势 + 机器人的安全与辅助能力”，在仿真中完成多角度抓取、避障接近、拾放等任务。
4. **泛化**：把“一次任务的演示”变成“一类任务的能力”。
5. **实体迁移**：同一套接口与状态机可替换为真实 ABB + 真实三指手（其底层自适应抓取代码与抓握成功状态机已存在），仿真中的抓取判定必须与实体状态机语义对齐。

### 1.2 “泛化”的三层含义（必须分清，路线不同）

| 层级 | 含义 | 技术手段 | 本路线定位 |
|---|---|---|---|
| L1 通用遥操作 | 同一套系统，人可以用手完成任意任务（任意抓取角度、任意障碍布局），不需要为每个任务改代码 | 任务无关的位姿映射 + 碰撞检查 + 手势命令 | 主线，必须完成 |
| L2 共享自治 | 机器在人的意图上叠加自主辅助：预抓取位姿对齐、接近方向吸附、避障减速/修正、抓取完成自动确认 | 局部规划 + 技能库 + 抓取 oracle | 主线后半段 |
| L3 演示学习 | 从人类遥操作演示中学习策略，使系统能自主或半自主复现任务（泛化到未见物体位姿/角度） | 行为克隆 / ACT / 扩散策略等模仿学习 | 可选高阶目标，单独验收 |

路线原则：**先做 L1，再做 L2，L3 按 L1/L2 的演示数据量与 GPU 预算决定是否启动。** L1/L2 本身已经满足“根据人手运动完成各类任务”的实用目标（人始终在环，泛化来自人的适应能力 + 机器人的安全约束），L3 追求的是“人去环”。

## 2. 现状盘点（决定路线的事实清单）

### 2.1 可以直接复用（已实测）

- 仿真栈：Gazebo 11 + ROS Noetic + MoveIt 1，demo_gazebo.launch 可一键冷启动机器人 + 三指手 + 三个控制器（见 SIM_00_EXISTING_ROBOT_AUDIT.md）。
- 独立安全包 handarm_sim_demo：fail-closed 仿真 guard、主动就绪协调器、PlanningScene 与 Gazebo 场景同步、统一手命令接口 hand_commander.py（OPEN/CLOSE/PRE_SHAPE_A/PRE_SHAPE_B/HOLD/STOP，27/27 命令实测通过）、静态障碍避障基线（23/23 成功 + 2 个负例安全失败）、已知位姿确定性抬升基线（SIM_01..03）。
- MoveIt Servo 速度链路已存在（/servo_server/delta_twist_cmds -> abbarm_velocity_controller），20 ms 发布周期已配置（config/servo_abbarm_velocity.yaml）。
- 感知资产：HaMeR crop-only（conda hamer_rtx2060，Py3.10，torch 2.2.0+cu118）实测可用；ROI provider（KLT 跟踪 + MediaPipe 一次性存在性检测）；RGB-D 会话录制/回放/评价基础设施；HaMeR 推断约 41 ms、5 Hz 调度下显存峰值约 4962 MiB（FP16+Gazebo headless）。
- 三指手模型：4 主动关节 f1j1（展合, 0..3.14 rad）、f1j2/f2j1/f3j2（弯曲, 0..1.3963 rad），4 个 mimic 关节；指尖 link 为 f1link3/f2link2/f3link3；手与 tool0 通过固定结构连在腕部（handbase_link 与 tool0 是 flange 的两个固定子链）。

### 2.2 已实测否决 / 必须修复（不能沿用的部分）

1. **HaMeR 的绝对姿态不可用**：global_orient 及由其派生的 MANO joint/rigid-vertex 掌坐标系在纯平移与开合中产生 60–180 度级假旋转（P3/P4 报告），其任何姿态字段**禁止**进入机械臂姿态通道。
2. **稀疏 KLT + Kabsch 相对跟踪不达标**：静止累计姿态 P95=18.6 度（要求 <5 度）、纯平移假旋转 P95=11.1 度（要求 <10 度）、有效覆盖 <90%（P5 报告），不能作为连续相对姿态源。
3. **旧 MediaPipe 位姿链已否决**（RD-002）：R_delta=(A R0)^T(A Rn)=R0^T Rn 代数抵消映射矩阵，且缺少工具共轭映射 R_EH @ delta_R_hand @ R_EH^T。
4. **Servo 配置不安全**：check_collisions: false、奇异阈值放宽为 100/200（servo_abbarm_velocity.yaml:41,49-50）；按 RD-009 还需要 controller 侧 watchdog 与故障注入测试。此状态禁止接真实机械臂，也**不应用作正式遥操作仿真基线**。
5. **仿真无抓取判定**：三指手无接触传感器、无力/摩擦参数，现有“确定性抬升”用 Gazebo fixed joint 附着，明确 physical_grasp_claimed=false。必须新增仿真抓取 oracle，才能与实体自适应抓取状态机对齐。
6. **工程卫生**：工作区根目录不是 Git 仓库；D455 目前 USB 2.1（正式必须 USB3 直连）；realsense2_camera ROS 包缺失；URDF 存在 xacro 与静态文件漂移；SRDF 禁碰对过宽。
7. **性能约束**：RTX 2060 6 GiB，85% 上限 5222 MiB；HaMeR FP16 + Gazebo headless 已用 4962 MiB，剩余约 260 MiB，禁止同时开 Gazebo GUI/RViz/浏览器 GPU 页面/GPU 检测器。

### 2.3 结论

**感知方向估计是全局瓶颈**：位置（手腕/掌心的度量深度反投影）和手势（指节角度）已有可信技术路线，唯独“人手 6-DoF 姿态”在现有实测里没有任何一个单独来源达标。整条路线围绕这个瓶颈设计：**增量高帧率跟踪 + 绝对低频锚点 + 离合重置 + 腕部标记兜底**（见 §4）。

## 3. 总体系统架构

（ASCII 架构图，见 §3.1 流程；此处给出数据流描述）

真实世界（操作员侧）：人手 -> D455 (RGB8 + aligned Z16, 640x480@30, USB3 直连)
感知进程 (conda, 非 ROS)：
- ROI: MediaPipe 存在性检测(低频) + KLT 掌区跟踪(高频)
- 位置: HaMeR 腕/掌关键点 + 深度中值反投影 -> 相机系米制位置 (5 Hz 锚点)
- 姿态: 掌区稠密 ICP/点到面配准 -> 高频增量位姿 (15-30 Hz)
- 姿态融合: SE(3) 增量融合 + 低频绝对锚点校正 + 离合(clutch)重置
- 手势: HaMeR hand_pose(15x3x3) / 指节角度 -> 手势状态机(带滞回)
- 输出: 加固的 UDP JSON 桥(seq/版本/CRC/会话/双时间域)
ROS 系统 (Noetic, 仿真)：
- teleop_bridge: UDP->ROS, 乱序/迟到/心跳门禁, /hand_pose, /gesture
- teleop_mapper: 离合/缩放/死区/SE(3)滤波 + 工具共轭映射 -> /target_ee_pose
- teleop_supervisor: 工作空间包络/速率钳制/watchdog/Servo 状态锁存
- pose_tracker: /target_ee_pose -> /servo_server/delta_twist_cmds
- MoveIt Servo: check_collisions=TRUE, 奇异阈值正常, 碰撞减速/停止
- scene_manager: 静态+动态障碍 -> PlanningScene
- gesture_gateway: /gesture -> hand_commander(OPEN/CLOSE/PRE_SHAPE/HOLD/STOP)
- grasp_oracle: 指尖接触传感器 + 提升测试 -> 抓取成功/失败(与实体状态机对齐)
- task_manager: 任务状态机(接近->抓取->抬升->转移->放置) + 共享自治辅助

**关键设计决策：**

- **感知进程与 ROS 解耦**：conda Py3.10 无法 import 系统 rospy(Py3.8)，维持“独立进程 + UDP JSON + ROS 桥”模式（现有 d455_conda_udp_sender_servo_v3.py 的同构升级），但协议必须加固（见 §4.6）。备选：rosbridge/ZMQ，二者皆可，选其一后统一。
- **位置/姿态/手势三通道独立**：任何一通道失效不拖垮其余通道（例如手势失效时机械手保持 HOLD，姿态失效时 Servo 输入超时归零——现有 0.5 s target timeout 语义保留）。
- **仿真中“相机是真实的、机器人和手是虚拟的”**：D455 观察的是真实操作员人手；仿真机器人跟随。这使感知链在仿真阶段就是最终形态，实体阶段只替换执行侧。
- **回放模式作为回归测试**：用已录制的 RGB-D 会话离线重放同一感知链驱动仿真机器人，实现可重复的端到端评价（现有 replay_rgbd_relative_tracker.py 同构升级）。

## 4. 关键技术方案

### 4.1 相机与驱动路径

| 项 | 决策 | 理由/依据 |
|---|---|---|
| 连接 | USB 3.x 直连（不用 Hub） | RD-012：USB2.1 只允许降级开发，正式链路必须 SuperSpeed |
| 流配置 | RGB8 + depth aligned to color, Z16, 640x480@30 | 现有已验证 profile（P3/P4 报告） |
| 时间戳 | 用 color_timestamp_ms 与 timestamp_domain，不用名义 FPS | P5 已冻结的契约 |
| ROS 驱动 | 安装 ros-noetic-realsense2-camera 供 TF/时间同步与话题化；推理仍走 conda 环境 | 当前该包缺失（P0 审计 §9.3）；推理环境已实测稳定，不迁移 |
| 数据录制 | 沿用 recorder/verifier（raw Z16 + aligned Z16 双份、双内参、逐文件哈希） | P2 基础设施，回放与评价依赖它 |

### 4.2 人手位置估计（低风险，直接实现）

- 主方案：HaMeR MANO **wrist 关键点**（21 joints 之 0 号）+ 其邻域 aligned depth 中值/MAD 门限反投影 -> 相机系米制位置；5 Hz 锚点 + 高频插值（用 ICP 增量）。
- 冗余方案：掌部 ROI 深度质心（去边缘、深度连续门限），当 HaMeR 帧失效时兜底。
- 出口门禁：录制静态/平移/开合三组会话，位置误差 P95 < 10 mm（静态）、平移轨迹与真值（可用腕部 AprilTag 作为参考真值）相关性 R²>0.95、无 >50 mm 尖峰。
- 注意：**HaMeR 平移输出未单独做过稳定性验收**（P3/P4 只验收了姿态），必须补测；失败则完全退化为“ROI 深度质心 + ICP 增量”。

### 4.3 人手姿态估计（全局瓶颈，必须做受控实验再定）

已知事实：HaMeR 绝对姿态禁用（§2.2-1）；稀疏 KLT-Kabsch 禁用（§2.2-2）。三条候选路线按优先级做**同一组门禁实验**（复用 P5 的门禁标准：静止累计 P95<5 度、纯平移假旋转 P95<10 度、有效覆盖>90%、无未拒绝单帧 >30 度、失败正确进入 FROZEN/LOST、重捕获不自动续接）：

| 路线 | 做法 | 优点 | 风险/代价 |
|---|---|---|---|
| **A. 稠密点到面 ICP（推荐首选）** | 掌部 ROI 深度点云（去边缘/去指节区），连续两帧 point-to-plane ICP + 法向一致拒绝 + 门限（Open3D 或 PCL），输出 SE(3) 增量 | 比稀疏 KLT 用更多几何信息，对平移/开合更鲁棒；CPU 可跑；无需新模型 | 大角速度/遮挡仍可能失效；需调参；需离合重置累积漂移 |
| **B. 腕部 AprilTag 标记（推荐兜底/参考真值）** | 操作员腕带/手背贴小 AprilTag，D455 单目解算 6-DoF（PnP + 深度），30 Hz | 位姿精度高、稳定、绝对、无漂移；同时给 A 路线当**真值参考** | 需要佩戴标记；遮挡时失效；非“纯裸手” |
| **C. 深度学习方法（备选）** | 换/加一个绝对姿态更强的模型（如 MediaPipe 关键点姿态做低频锚点，或手部 6-DoF 专用模型） | 绝对、无漂移 | 6 GB 显存几乎无余量；MediaPipe 姿态抖动未经验证；新增 GPU 负载需重测显存峰值（RD-011 约束） |

**推荐架构（混合）**：A + B + 离合。

- 高频（15–30 Hz）：A 的 ICP 增量做运动估计；
- 低频（30 Hz，若佩戴标记）：B 的绝对位姿做锚点/漂移校正，同时作为 A 路线的开发期真值；
- 离合（clutch）时把当前手位姿定义为参考 I，消除累积漂移与“手不在工作区”的歧义；
- 融合形式：SE(3) 上的互补滤波 / 简化 EKF（状态：当前 R_B_H、t_B_H；观测：A 的增量、B 的绝对）。**禁止**用低通滤波掩盖定义性失败（P3/P4 的教训：假旋转是定义错误，不是噪声）。

若 A 路线通过门禁，则 B 降级为开发/标定工具（不要求操作员日常佩戴）；若 A 不通过，B 直接成为正式姿态源——这是保证路线不阻塞的兜底。

### 4.4 手势识别 -> 机械手命令

**原则：手势通道与 6-DoF 通道解耦；离散命令优先，连续构型重定向次之。**

特征源（二选一，按实验定）：HaMeR hand_pose（15x3x3，MANO 指节旋转）或 MediaPipe 21 landmarks（已在 conda 环境可用）。将特征归一化为每指弯曲角 θ_i 与对掌度 a。

**v1 离散手势（必须）**，手写规则 + 滞回 + 停留确认（如 300 ms 持续）：

| 手势 | 特征判据（示例） | 机械手命令 |
|---|---|---|
| 五指张开 | 全部 θ_i < 阈_A | OPEN |
| 握拳 | 全部 θ_i > 阈_B | CLOSE（仿真中触发“自适应闭合”，见 §4.8） |
| 捏合（拇-食指） | 拇指对掌度高、拇食指间距小 | PRE_SHAPE_A（精密构型） |
| 三指张开成爪 | 展合度大、弯曲中等 | PRE_SHAPE_B（包裹构型） |
| 张开手掌朝向相机 | 掌心法向对准相机且张开 | STOP（锁定机械手，不改手臂） |
| 拳头静止 / 脚踏 / 键盘 | 离合确认 | CLUTCH 开/关 |

**v2 连续构型重定向（可选加分）**：把拇指对掌角映射到 f1j1（展合）、把三指平均弯曲角映射到 f1j2/f2j1/f3j2（弯曲，共用或分指映射），使“构型变换”连续化。接口收敛到 hand_commander 的关节目标，实体侧则映射到其自适应抓取状态机的预抓取/抓取模式。

**出口门禁**：录制的三组真实会话（含开合动作）上，手势分类 confusion matrix 各类正确率 ≥95%，误触发率（静止 HOLD 期间出现非 HOLD 命令）<1 次/分钟，命令切换无振荡（同一命令两次切换间隔 ≥500 ms 的滞回验证）。

### 4.5 坐标映射与遥操作数学（本项目最需要“写对”的部分）

**坐标系**：C=D455 color 系，H=手掌系，B=机器人基座系（仿真中即 world/规划系），E=末端 tool0 系。

**标定**：眼到手（eye-to-hand，相机固定观察操作员）。映射只用“增量 + 参考点”，因此**只需知道 C->B 的旋转对齐 R_CB，不需要精确的相机-基座平移**（平移在增量差分中被消掉）。R_CB 在仿真阶段由遥操作工作区定义直接给出（操作员参考系与机器人 world 系对齐）；实体阶段用手眼标定（easy_handeye 或 AprilTag 板 + AX=XB）。

**离合（clutch）**：t0 时刻记录 R_C_H(t0)、p_C_H(t0)、R_B_E(t0)、p_B_E(t0)；只有离合态才产生运动。

**位置映射**（含缩放与死区）：

    p_B_E(t) = p_B_E(t0) + k_pos · R_CB · ( p_C_H(t) − p_C_H(t0) )

**姿态映射**（手部相对旋转 -> 工具共轭，修正 RD-002 的代数抵消）：

    R_delta(t) = R_C_H(t0)ᵀ · R_C_H(t)              # 手在自身系内的相对旋转
    R_B_E(t)   = R_B_E(t0) · R_EH · R_delta(t) · R_EHᵀ

R_EH 是把“手掌体轴”对齐到“工具体轴”的常量旋转（例如手背俯仰 -> 夹爪俯仰），在离合时由 R_EH = R_B_E(t0)ᵀ · R_B_H(t0) 估计并冻结。这就是审计要求的 R_EH @ delta_R_hand @ R_EH.T 工具共轭映射：手绕自身轴转多少，工具就绕自身对应轴转多少。

**后处理（在映射之后，不改姿态定义）**：

- SE(3) 平滑：旋转用四元数 slerp / 指数映射，平移用二阶 Butterworth；
- 速度/加速度钳制（k_pos 建议 1.0，速度上限建议初期 0.15 m/s、0.3 rad/s，随后按实测放宽）；
- 工作空间包络：超出定义盒 -> 输出被钳制并报 WARNING，不产生跳变；
- 映射输出为 /target_ee_pose（沿用现有话题契约），由 servo_pose_tracking_node_v2 风格节点转成 Servo Twist 增量。

### 4.6 通信与安全协议（加固现有 UDP 桥）

沿用“conda 独立进程 -> UDP JSON -> ROS receiver”结构，但协议必须补齐（P0 审计 §3.1 列出的缺口）：

- 报文：协议版本 + 会话号 + 递增序列号 + 采集时间戳（device domain）+ 发送时间戳（host monotonic）+ CRC32；
- receiver 侧：乱序丢弃、迟到（>120 ms）丢弃、时间倒退拒绝、心跳超时（500 ms）-> 输出 HOLD/零速、状态锁存（RD-009：Servo 进程失联不等于 controller 收到零速，必须另有 watchdog 停机路径）；
- 所有 NaN/Inf 在发送与接收两侧 fail-closed。

### 4.7 控制层与避障（仿真侧）

1. **Servo 安全化**（前置条件，进入遥操作联调前必须完成）：
   - check_collisions: true、collision_check_rate 保持 10 Hz；
   - 奇异阈值恢复 MoveIt 参考值（lower≈17、hard-stop≈30 量级，针对 IRB120 实测标定，不再是 100/200）；
   - 0.10 s 输入超时 + 状态码锁存 + supervisor 限速；
   - 执行 RD-009 要求的故障注入：Servo 进程 SIGKILL、发布者消失、心跳中断三种场景下机器人在规定时间内停住。
2. **避障**：跟随模式下避障由 Servo 碰撞检查实现（接近障碍 -> 减速 -> 停止），**人负责绕障路径、机器人负责安全包线**——这正是“泛化到任意障碍布局”的机制，与现有静态障碍规划基线（SIM_02）互补而非替代。动态障碍：Gazebo 移动模型位姿经 scene_manager 高频（10 Hz）刷新进 PlanningScene，或后续接入仿真深度相机点云 + Octomap（当前 sensors_3d.yaml 为空）。
3. **抓取期模式切换**：接近/抓取阶段从“增量跟随”切到“任务空间辅助”（见 §4.9），避免 Servo 高频抖动破坏抓取精度。

### 4.8 仿真抓取判定（对齐实体自适应抓取状态机）

现状：仿真三指手无接触传感器（SIM_KNOWN_LIMITATIONS #3）。需要新增：

1. **指尖接触传感**：在 f1link3/f2link2/f3link3 加 Gazebo contact sensor（bumper 插件或自定义 contact plugin，发布接触状态话题）。同步给指尖碰撞网格设置摩擦参数（否则“抓得住”无物理意义）。
2. **仿真自适应闭合**：CLOSE 命令改为“闭合直到接触”——任一指尖接触或关节速度趋零即停止，模拟实体的自适应抓取（实体代码已有的行为）。
3. **抓取 oracle 状态机**（与实体状态机同名同义，便于替换）：

    APPROACHING -> CONTACTING(≥2 指接触持续 200ms) -> CLOSING_STABLE -> LIFT_TEST
      -> SUCCESS(物体跟随 EE 位移>阈值且滑移<阈值) | SLIP/FAIL(超时或滑移) -> RELEASE/REPLAN

4. 物体侧判据：物体相对手指的位姿变化、抬升测试（抬 30–50 mm 后物体仍与手指贴合）。现有 deterministic attach 插件保留作为“已知位姿搬运”的调试工具，**不得**冒充物理抓取成功。
5. **接口对齐**：oracle 输出 grasp_success/quality/slip，实体侧由底层自适应抓取状态机提供同名字段——仿真与实体共用 task_manager 上层逻辑，替换点仅此一处。

### 4.9 共享自治（L2 泛化的核心机制）

在 L1 遥操作基础上叠加，全部可开关（默认开，可一键退回纯 L1）：

1. **预抓取辅助**：目标物位姿已知（Gazebo/PlanningScene 查询或视觉检测）时，当 tool0 进入目标邻域，自动把末端朝向吸附到最近抓取轴（对物体主轴的离散采样抓取姿态集，OMPL 可达性过滤），人手继续负责位置；
2. **接近方向辅助**：抓取阶段把人的自由 6-DoF 输入投影到“沿接近轴 ± 正交微调”子空间，降低抓取失败率；
3. **避障辅助**：人输入的 Twist 与 Servo 碰撞减速融合（碰撞检查已天然提供）；
4. **技能库**：OPEN/CLOSE/PICK/PLACE/PRE_SHAPE 等以参数化技能形式封装，手势或任务状态机触发，实现“手势选技能 + 手位置连续控制”的混合模式。

### 4.10 演示学习（L3，可选）

- 数据：L1/L2 阶段已天然产出演示数据（手位姿、映射后目标位姿、手势命令、机器人状态、抓取 oracle 结果、任务成败标签），沿用现有 session 录制格式扩展字段即可；
- 算法：先行为克隆（MLP/轻量 ACT）复现“接近->抓取”子任务，再扩展扩散策略（diffusion policy）；
- 显存现实：RTX 2060 6 GiB 训练受限——小模型（<10M 参数）可在本机短训，正式训练建议导出数据到服务器；推理侧轻量模型可与 HaMeR 分时共享 GPU（重测显存峰值）；
- 验收：L3 单独设门禁（仿真任务成功率 ≥70% 且可泛化到未见物体位姿/角度，失败可被 L2 辅助兜底），不达标不阻塞 L1/L2 交付。

## 5. 性能与时延预算（6 GiB GPU 下的硬约束）

| 环节 | 预算 | 依据/说明 |
|---|---|---|
| HaMeR | 5 Hz 调度、FP16 或 FP32 二选一实测 | FP16 峰值 4962 MiB（含 Gazebo headless），仅剩 260 MiB；FP32 峰值 3514 MiB，余量约 1.7 GiB。**若需并发 GPU 检测器，选 FP32 HaMeR**（RD-011：实测为准，不假设 FP16 省显存） |
| ICP / 姿态跟踪 | CPU，掌部 ROI（<200x200 点云），15–30 Hz | P5 实测稀疏管线 CPU 单帧 P95≈27 ms；稠密 ICP 需重新实测，超预算则降帧率或用降采样 |
| Servo 循环 | 20 ms（50 Hz） | 现有配置 |
| 端到端时延目标 | ≤150 ms（跟随模式），≤250 ms（抓取辅助模式） | 增量映射下恒定延迟只产生滞后不产生偏置；回放模式实测验证 |
| 显存红线 | 系统总峰值 < 5222 MiB；任何新增 GPU 模块先重测峰值 | RD-005/011 |
| 运行纪律 | 遥操作联调期间禁止 Gazebo GUI/RViz/浏览器 GPU 页面与感知进程并存 | RD-011；GUI 复核用回放/截图 |

## 6. 分阶段路线图（每阶段有出口门禁）

> 时间估算为单人全职工作量，供排期参考。每阶段必须留下“实测结果 + 运行命令 + 结果 JSON/CSV”，沿用本项目证据文化（见 SIM_FINAL_CHANGELOG.md 的做法）。

### 阶段 0：架构冻结与工程卫生（约 1 周）

**工作项**
- 本路线评审定稿（冻结接口契约：话题/消息、映射公式、安全 profile、手势集）；
- 工作区根目录 git init + 完善 .gitignore（排除 build/、devel/、_DATA/、嵌套 .git），首次提交干净快照；
- 安装 ros-noetic-realsense2-camera；确认 D455 USB3 直连（完成 USB3 认证 TODO 列表项）。

**出口门禁**：接口契约文档 + Git 初始提交 + USB3 枚举 PASS + realsense2_camera 可发布彩色/深度/对齐话题。

### 阶段 1：感知升级（位置 + 姿态 + 手势）（约 3–4 周）

**工作项**
- 位置链：HaMeR wrist + 深度中值反投影（§4.2），录制三组验证会话；
- 姿态链：实现稠密 ICP（§4.3 路线 A）；搭建腕部 AprilTag 参考真值（路线 B）；跑 §4.3 门禁矩阵；实现 SE(3) 融合 + 离合；
- 手势链：v1 离散手势识别 + 滞回（§4.4）；
- 协议：加固 UDP 桥（§4.6），新 sender/receiver 一对；
- 回放工具升级：感知链离线重放同一会话，输出逐帧结果 JSON。

**出口门禁**
- 位置 P95<10 mm（静态）、R²>0.95（平移）；
- 姿态门禁按 §4.3 全绿（A 或 B 至少一条路线全绿，B 作为兜底）；
- 手势分类 ≥95% 且无误触发；
- 三组会话回放与实时输出一致性（相同帧输入 -> 相同位姿输出）。

### 阶段 2：遥操作映射与 Servo 安全化（约 2–3 周）

**工作项**
- Servo 安全 profile（碰撞开启、奇异阈值、超时、watchdog）+ RD-009 故障注入测试（§4.7-1）；
- teleop_mapper：离合/缩放/死区/平滑/包络 + 共轭映射（§4.5），单测覆盖映射公式（含与旧 R0ᵀRn 代数抵消的对照回归测试）；
- 联调：实时人手 -> 仿真 tool0 位姿跟随（位置+姿态），RViz 显示手姿与目标位姿。

**出口门禁**
- 三种故障注入（SIGKILL/发布者消失/心跳断）下机器人 ≤300 ms 停住；
- 跟随精度：慢速正弦轨迹（10 cm 幅值、0.5 Hz）位置误差 <15 mm、姿态误差 <8 度（由腕部标记真值评价）；
- 无 NaN/Inf 穿透、无包络外运动、无碰撞关断。

### 阶段 3：手势控制机械手 + 仿真抓取闭环（约 2–3 周）

**工作项**
- gesture_gateway 接入 hand_commander；指尖接触传感器（§4.8-1/2）；自适应闭合；抓取 oracle 状态机（§4.8-3）；
- 任务状态机 task_manager：approach -> grasp -> lift -> transfer -> place，共享自治 v1（预抓取辅助 + 接近辅助）；
- 端到端演示：人手遥操作从**多个角度**（正/侧/斜 45 度/低角度）抓取目标物并放至指定点；含障碍布局的接近任务。

**出口门禁**
- 抓取 oracle 与真值一致率 100%（接触/抬升判定 vs 事后人工标注）；
- 多角度抓取任务成功率 ≥80%（每角度 ≥10 次，失败必须落入 SLIP/FAIL 安全路径，不得崩溃）；
- 全程 Servo 碰撞检查开启、无安全违规记录。

### 阶段 4：任务泛化验证与技能库（约 3–4 周）

**工作项**
- 任务套件：多角度抓取、跨障碍拾放、桌面整理（3–5 物体）、构型变换任务（精密捏取 vs 包裹抓取）；
- 技能库与共享自治 v2（§4.9）；演示数据全量录制（§4.10 数据格式）；
- 记录泛化指标：未见障碍布局 / 未见物体初始位姿下的成功率、平均完成时间、安全违规数。

**出口门禁**
- 未见位姿任务成功率较训练场景下降 ≤15%；
- 至少 50 条带标签演示数据入库并通过格式校验。

### 阶段 5：实体迁移（约 4–8 周，与阶段 3/4 并行准备）

**工作项**
- 真实 ABB IRB120 与驱动/控制器接入（速度或位置模式按其控制器实测选择），硬件 E-stop、降速运行（≤0.1 m/s 起步）、独立 watchdog；
- 真实三指手驱动接入：把 hand_commander 命令映射到其自适应抓取状态机（OPEN/CLOSE/预抓取模式 + 抓握成功回执），**grasp oracle 由实体状态机替代**（§4.8-5 的接口对齐）；
- 手眼标定（§4.5）；同套任务套件实体复测。

**出口门禁**
- 实体抓取成功率与仿真同量级（允许 ±15% 环境差异）；
- 所有安全测试（故障注入、急停、包络、碰撞停止）在实体上重跑通过；
- 未经安全验收的速度/碰撞配置**禁止**载入实体控制器。

### 阶段 6（可选）：L3 演示学习

**工作项**：按 §4.10 执行，独立验收，不阻塞主线。

## 7. 风险登记

| 风险 | 概率/影响 | 缓解 |
|---|---|---|
| 稠密 ICP 同样过不了 §4.3 门禁 | 中/高 | 路线 B（腕部 AprilTag）直接成为正式姿态源；路线已预设兜底 |

| Servo 碰撞开启后跟随卡顿/误停 | 中/中 | 逐场景调 collision proximity；抓取期切任务空间模式（§4.7-3） |
| 仿真接触传感器/摩擦不真实导致 oracle 与实体不一致 | 中/高 | 只对齐“状态机语义”而非物理数值；实体阶段用真实状态机替换 oracle（§4.8-5） |
| 离合/手势误触发导致危险运动 | 低/高 | 双通道确认（手势+停留时间，或脚踏开关）、监督器限速、watchdog（§4.4/4.6） |
| 实体控制器与仿真接口差异 | 中/高 | 阶段 5 前置硬件验收；速度/位置模式二选一实测（P0 审计 §6.3 已提示该歧义） |
