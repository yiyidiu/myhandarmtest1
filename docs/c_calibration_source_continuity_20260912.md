# C后姿态跳变：姿态来源切换的直接原因与修复

用户澄清的问题是：手基本不动，按C后末端突然变姿态；不是要添加按C后的运动门槛。上一轮4毫米首次位置保持处理错了对象，已经撤销；实时入口也不再调用此前的C后1.5°姿态保持。这里用未冻结的位置和姿态重新定位。

## 原录像中实际发生的事

当前最新可用记录仍为 `hand_motion_observation_20260911T202058_Ime9`，对应录像1:05附近。C接受的是第1070帧，录像时间65.3026秒；之后第一条控制观测是第1073帧，65.4029秒。

| 量 | C标定帧 | 下一观测帧 |
|---|---:|---:|
| 前臂结果距当前的时间 | 149毫秒 | 221毫秒 |
| 前臂结果是否参与手部姿态 | 是 | 否，超过当时200毫秒有效期 |
| 前臂引入的姿态修正 | 1.144° | 0 |
| 原始手模型滤波后姿态相对C帧的变化 | 0 | 0.184° |
| 实际发送姿态相对已记录手C零位的变化 | 0 | 1.152° |

**直接错误是：手C零位记录了带前臂修正的姿态，后续帧却切回不带修正的姿态。** 两套结果相减，前臂修正量的消失被当成人手转动，再通过旋转增益变为机器人目标。

C的首个机器人目标确实等于当时机器人零位，未发现标定当帧就给错初始目标。异常开始于紧随C的下一条输入，符合录像中“刚按C便偏转”的时序。当前证据支持这条直接原因，不意味着所有静止变化都由它造成。

这个不稳定的前臂融合是此前工程中加入的处理，不能把它归咎于用户手没放稳，也不能靠C后禁止小动作掩盖。

## 修复方式

- 实时控制始终使用同一条滤波后的MANO手部姿态，标定和后续观测定义一致。
- 前臂估计即使通过环境变量开启，也只写入诊断候选，不再更改控制姿态。其有效、过期和置信度变化不能切换控制姿态来源。
- 删除上一轮新增的位置保持；实时入口停止调用C后的姿态保持。既不减小旋转增益，也不移动手C或机器人C。
- 原有有效标定帧确认、真实丢手处理、常规姿态滤波及机器人碰撞保护保留。显示窗口明确标注处理后的控制观测，避免把诊断候选误当控制输入。

前臂融合在上一轮已默认关闭，但仍存在显式开启后进入控制的路径；本轮从实时控制数据路径排除了它，同时用不依赖C后冻结的对照验证原因。不能把这描述成“本轮第一次发现所有问题”或“现在所有视觉误差都已修好”。

## 因果验证和实际仿真

第一项只固定真实C帧的HaMeR姿态，重现前臂由有效变过期，其他条件不变：旧流程凭空产生1.144°手部相对姿态、约2.979°机器人目标转动；修改后两者为0。这是隔离软件来源切换的对照，不是新真人数据。

第二项把原录像相同位置、相同时间间隔的输入送入Gazebo，标定及观测均使用相应版本的同一通道，无C后冻结：

| 结果 | 旧来源混用 | 修复后单一来源 |
|---|---:|---:|
| 静止短段实际末端总转角峰值 | 3.88° | 1.96° |
| 静止段末端最终相对C的局部XYZ角 | 2.61° / −0.12° / 2.87° | −0.09° / −0.10° / 1.96° |
| 同段实际位置变化 | 1.72毫米 | 1.67毫米 |
| 独立5°横滚输入后的实际末端转角 | 14.96° | 14.95° |

静止短段为真实65.303–66.071秒输入，随后保持最后一帧0.8秒观察延迟响应。结果表明来源切换造成的偏转被移除，但原手部估计变化仍经映射产生约1.96°末端变化。因此，**“这条C相关错误路径已修正”和“手基本不动时末端完全不动”不是同一个完成结论，后者尚未实现。**

第三项经过生产用C确认逻辑、UDP接收、ROS映射和Gazebo，给入完全不变的手姿态，分别首次按C、主动转动后保持手姿态不变再按C：首次标定前后实际最大转角约0.092°、位置变化0.44毫米；第二次约0.067°、0.25毫米。未复现数度级标定跳变。这个合成输入实验用于排查标定重置，不能代替真人静止精度验收。
