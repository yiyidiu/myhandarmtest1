# 连续帧修正：本轮实际结果与未上线原因

目标：静止时稳定；平移、俯仰、横滚时减少不期望的其他转动；保留主动小角度及同时平移、多个转轴组合。用户原有小角度映射、C 参考和可运行版本均保留。

**本轮没有得到可替换运行版本的修复。所有模型只进行了离线计算，没有接入相机运行入口或机械臂，没有进行抓取试验。**

工作基于 `c007817`，离线研究保存在 `codex/continuous-intent-correction-20260912` 分支。原运行源码和配置没有被本轮改动。试验输出位于 `.runtime/continuous_intent_20260912/`；输入来自 9 月 11 日两次、9 月 12 日一次手部观测记录。

## 实际采用的方法

输入包含当前 HaMeR 位姿、最近约一秒的变化，以及已有图像关键点和真实深度的连续变化。输出为三个可同时存在的连续转动修正量，不用“平移/俯仰/横滚三选一”控制其他轴。

首先尝试保留每次新增转角中的可信部分，再累加得到姿态。随后因完整连续回放暴露累积偏差，改做对原 C 相对姿态直接预测修正的对照。后者不累加被删减的转角，不新增 C 专用冻结或重新定义零点。

## 单段改善不能代替连续控制

下表使用 `hand_motion_observation_20260912T145617_iJYZ`。数值为**进入原映射增益之前，按实际映射轴顺序分解的手部指令角度**，不是 IMU 真值，也不是 Gazebo 末端实测角度。单段峰值相对裁去边界后的片段首帧计算。

| 对照 | 原输入 | 删减新增转角后累加 | 直接修正原 C 相对姿态 |
|---|---:|---:|---:|
| 1:43–1:47 右移时附带横滚峰值 | 19.62° | 0.03° | 19.67° |
| 2:49–2:51 主动俯仰峰值 | 60.22° | 59.64° | 61.35° |
| 3:19–3:21 主动横滚峰值 | 36.51° | 36.18° | 36.65° |
| C 后静止段附带横滚峰值 | 1.85° | 1.25° | 1.86° |

右移、后两段主动转动参与了开发期验证与模型选择，**不是未见过的最终测试集**。最新 C 段未参与训练及自动选择；但反复查看这些结果仍属于开发过程，不能声称人群泛化。

将第一种处理连续应用于整段数据，仅在实际 C 参考更换时重置，而不在每个标注片段开头重置：

- 3:34.83 的输入俯仰、横滚、偏航为约 **[0.80°, −1.40°, −2.53°]**；
- 处理后却为约 **[2.73°, −24.53°, −15.11°]**。

原因是去程与回程删减比例不同，被删除的角度不会自动抵消。这个问题属于**本轮未上线模型的输出方式**，不能拿它解释历史录像中原控制器的故障。逐段归零的计算掩盖了该问题，因此上述 19.62°→0.03°不能作为修复成功。

第二种直接修正没有这项积分累积机制。在整段输入接近 C 的检查点中，修正量最大约 0.061°。理想几何对照中，先偏航 30°再平移，输出偏航约保持 30.19°–30.42°；输入完全返回零时输出也为零。但它对真实右移串动及 C 后波动几乎没有改善，不能因此推荐运行。

## 能下的结论

1. 连续信息可以带来局部抑制，但目前没有得到同时减少串动、保留主动组合动作、且不破坏回零对应关系的控制结果。
2. “可同时输出三个轴”只解决了互斥分类的限制，没有证明模型能辨认哪些转动是用户期望的。
3. IMU 测到的真实转动也可能包含用户不想传给机器人的自然耦合，不能直接作为意图标签。理想几何组合动作只检查输入保留能力，也不能替代真人意图正例。
4. 现有标注明确的组合动作主要是偏航加平移，缺少与非期望耦合相近幅度的主动俯仰、横滚、平移组合对照。但**不能认定失败仅由数据量造成，更不能保证补录几十秒就能修复**。本轮已发现的输出累积问题必须独立处理。

当前决定：停止继续扫描参数，保留可用运行版；不让用户验收这些失败模型。下一项直接实验只应回答“相近幅度下，已有图像/深度线索能否区分主动组合转动和附带耦合”，再决定是否值得继续训练。此前提出的约 40 秒补录暂缓，本轮未启动采集。
