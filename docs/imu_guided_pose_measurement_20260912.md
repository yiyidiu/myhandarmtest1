# 用 IMU 检查并修正视觉姿态：本轮实际结果

目前只能确认**左移时的视觉多估转动有所减少，主动横滚的转动量更接近 IMU**。左移的剩余误差仍大，静止抖动基本未改善，部分动作略有退化，尚未达到精细遥操作要求。修正版为独立开关，默认关闭；没有把它替换成默认控制版本。

本轮先处理测量：使用真实 RGB-D 掌部区域辅助修正 HaMeR 姿态，用已录制 IMU 的真实转动量拟合参数和对照。没有加入意图分类、平移时锁姿态、单轴动作锁其他轴或人手弧线补偿。IMU 不参与运行时控制，也没有改 HaMeR 网络权重。原机械臂映射增益、控制器、碰撞设置和物体场景均未调整。

## 改动具体做了什么

1. 用腕部和四个掌指关节的二维位置圈定掌部内部区域，从真实深度拟合掌面，再恢复掌面方向和掌部纵向方向。这样多了一个来自 RGB-D 几何的姿态观测，避免只根据手在画面中的位置整体旋转 HaMeR 结果。
2. 从较早录像的 IMU 转动量拟合修正权重。输入包括相对 C 的水平视角变化、RGB-D 与 HaMeR 的方向差。平移片段中 IMU 实测出的真实转动照常保留，没有把“平移意图”当成零转动标签。
3. 只对修正量做约 0.365 s 时间常数的平滑，减少深度噪声直接传入姿态。大幅相机 Y 轴转动的测量响应作小幅校准，5°以内不施加该响应增量。机械臂原有的“手转5°→机械臂转15°”等映射参数没有修改；修正视觉读数本身仍会改变传入映射的值。
4. C 的手姿态和辅助掌面使用同一帧作为固定参考；辅助深度暂不可用时延续已估计的修正，不突然切回未修正姿态。没有新增 C 后冻结、死区或准许运动的条件。关闭开关时保持原测量路径。
5. 窗口中的处理后坐标轴取实际发出的修正姿态，记录同时保存掌面观测和修正量。深度时间与 RGB 时间不匹配时，不使用这帧的辅助掌面；原位置、手指和基础姿态通道继续按原规则工作。

独立复算中，真实深度图的掌面拟合耗时中位数约 1.20 ms，姿态修正约 0.18 ms。这是缓存帧上的 CPU 耗时，不是相机—机械臂端到端延迟；修正量的平滑也可能带来动态滞后，不能据此声称遥操作延迟已改善。本轮没有启动真人采集或 Gazebo 验收。

## C 跳变与当前残差

此前已找到并修复的是：C 记录时包含前臂修正，后续帧因前臂观测超时移除修正，即使 HaMeR 几乎不变也会向机械臂产生姿态变化。本轮保留这一修复。

本轮用同一恒定手姿态、不同标定姿态以及重复 C 检查，没有新增标定引起的转动；真实旧录像中仍有约 2° 的静止视觉波动，不能用恒定输入的软件检查掩盖它，也不能声称“真人手不动，机械臂就完全不动”已经验证。

剩余瓶颈仍是视觉测量。掌部内部区域在现有录像中仅约 35×50 像素，深度掌面也存在波动，二维关节点的位置和掌部表面形状也会影响恢复方向。因此它目前是辅助观测，不是独立真值。直接增大几何修正权重或整体压小转角，不能保证只消除假转动。

现有数据能比较不依赖坐标安装方向的总转动量。分别用不同主动旋转段估计相机与 IMU 坐标关系时，结果尚不足以独立判定每个轴的误差；“总角度更近”不能升级为“俯仰、偏航、横滚均已对准”。在这个缺口解决前，不把剩余视觉误差交给意图分类器或弧线补偿吸收。

## 本轮对离线数据读取的更正

接入检查发现：RealSense 录像跳转后，有时同一 RGB 帧被配到另一深度帧。此前仅核对 RGB 帧号与时间，没有核对配对深度时间。较新录像的 C 帧和三处恢复帧受影响；较早录像 C 帧重新读取一致。重新预读并核对 RGB、深度时间后，更正了这些帧，二者时间差约 0.017–0.018 ms。另有三个旧稀疏缓存帧在对照验证时替换为时间匹配的读取。

本报告全部数字使用更正后的深度数据；此前阶段性提到的左移 42.3°→28.1° 结果已被 **42.3°→30.7°** 取代。源录像未修改，配对检查保存在 [seek_pair_repair.json](/home/dongtian/myhandarmtest1-teleop-repair/.runtime/imu_guided_pose_repair_20260912/seek_pair_repair.json)。
