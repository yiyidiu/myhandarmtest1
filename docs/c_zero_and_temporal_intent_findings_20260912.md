# 9月12日：按 C 后的转动从哪里来

目标是手保持不动时末端也保持稳定，平移与主动转动均能准确传递。当前只证明了下述原因和局部改善，**没有完成零位稳定及精细控制验收**。

输入为 `hand_motion_observation_20260912T145617_iJYZ`，录制版本为 `2a672ae1a7803c3b455092e052cb15b825defef3`。本次没有重新采集真人动作，没有使用 IMU 驱动机器人，也没有进行抓取验收。所有诊断数据位于该录制目录的 `analysis_feedback`。

## C 与后续停手的直接对照

用户指出“按 C 后手不动会转，后续停手却比较稳定”。只报告测量噪声或滤波减半，不足以解释这个区别。因此，用完全相同的已记录输入比较两种控制状态。

在独立、无物体的 Gazebo 中，保留录制版控制、映射比例和机械臂初始位姿：

| 输入及控制状态 | 末端相对该次机器人零位的最大总转角 | 最大目标转角 |
|---|---:|---:|
| 刚建立 C，输入录制的静止段 | 3.163° | 4.460° |
| 先输入 5°手部转动、返回并停稳，不重新按 C，再输入完全相同静止段 | 3.109° | 4.460° |
| 重新建立 C，输入数值始终完全不变 | 0.000151° | 小于 0.000001° |

静止段使用录像 70.560–72.4 秒的原始已发布位置和姿态，保持原采样间隔；最后额外保持末帧 0.65 秒观察机械臂响应，所以表中峰值不是原录像同时间窗的峰值。返回后第二次试验开始时仍有约 0.049°残差。该对照限定于这一段及这一初始状态，不能外推为所有 C 路径都不可能出错。

**结论：本次复现没有发现 C 初始化额外放大运动；同一段测量波动在返回停稳后依然会驱动机械臂。** 按 C 的第一帧目标与机器人零位一致，额外目标出现在随后变化的测量中。恒定输入对照也没有复现初始化跳转。

原录像 70.560–72.36 秒，已发布手部姿态相对首帧最大变化 2.440°，目标最大变化 4.460°，实际末端最大变化约 2.583°。后续 124–125.8 秒附近停手片段，实际末端相对片段首帧仍有约 2.256°变化。两个真人片段的姿态和运动历史不同，后者只是辅助观察，不能代替上面的相同输入对照。

因此，不把“人手没动”改写成“人手一定转了”；问题是视觉输出会变化，控制器把变化当成了动作。也不能据此断言用户过去每一次 C 异常都是同一原因。

证据：`control_comparison_signals.json`、`stationary_comparison_statistics.json`、`replay_c_state_contrast.py`、`c_state_contrast_actual_arm.json`。原始第五关节反馈在 C 前为 90.000°，本次没有改机械臂初始关节角。

## 已确定的一个测量原因

将 **同一张原始 RGB 图像保持不变**，只改为静止段里实际出现的裁剪框，HaMeR 原始姿态仍变化约 1.784°。这是裁剪影响姿态估计的直接证据，与真实手部转动无关。

使用实际连续图像时，原裁剪的原始姿态变化峰值为 3.774°；诊断性地固定裁剪框后仍有 2.962°。所以裁剪是一个原因，尚不足以解释全部波动。固定裁剪只用于这个因果对照，没有部署成手部移动约束。真实 RGB-D 的简单掌部方向估计也有明显噪声，不能把它当成精确真值；目前不能认定提高分辨率一定解决剩余问题。

证据：`probe_c_crop.py`、`c_crop_probe.json`、`c_rgbd/manifest.json`。RGB 与深度按各自时间戳核对，不以回放 seek 后的首张深度直接配对。

## 保存的抑噪试验及限制

新增的姿态滤波试验只在显式启用 `TELEOP_PRECISE_ORIENTATION=true` 时生效。利用最近观测转向是否一致，减少来回波动触发快速响应的情况；没有新增 C 专用冻结、死区或移动零点，没有更改手部 5°到机械臂 15°的原有映射。

同一静止段的 Gazebo 回放，实际末端最大转动约 3.165°降至 1.580°。固定 5°输入的最终目标仍为 15°，实际约 14.95°。这只是局部改善：残余转动依然存在，慢动作的动态延迟仍需考虑，不能称为已解决。较慢滤波在整段离线回放中还增加了 C 前四帧的姿态拒绝，需在扩大使用前处理；该记录 C 后未增加拒绝不等于所有动作都不会增加拒绝。

`run_precision_hand_observation.sh` 是独立试验入口，会关闭上一版 RGB-D 经验修正，**不是对上一版的全面替代**。关闭该修正在此前左移片段会失去部分误转补偿。普通入口默认行为保持原样；不得仅因静止段改善就推荐整体切换。原生分辨率参数已提供可选项，1280×720 只核对了设备支持，未完成真人精度及运行延迟对照。

证据：`c_noise_actual_arm.json`、`orientation_noise_candidate_summary.json`。原有回退入口仍为 `.runtime/version_backups/imu_guided_pose_trial_20260912/restore.sh`，恢复到本次录制使用的版本。

## 连续帧意图识别的实际结果

按用户标注，将较早整段录像用于训练、另一整段用于选择训练轮次，最新整段作测试，没有随机混合相邻帧。比较逐帧分类器与只看当前和历史帧的时序卷积网络。这里“因果”仅表示不使用未来帧，不表示因果推断或能够直接观测人的意图。

时序网络在最新录像已标注帧上的分类准确率约 53.4%，其中用户认为效果良好的 2:49–2:51 主动俯仰段，24 个评价时刻有 23 个被判为平移。**没有接入控制**，否则会压制用户明确需要的主动转动。这些帧不是独立实验样本，不能据此宣称人群泛化性能。IMU 存在接收时间异常，本次没有将接收时刻直接当作传感器真实采样时刻进行逐轴真值拟合。

方法依据为作者的 [TCN 论文](https://arxiv.org/abs/1803.01271)及[官方实现](https://github.com/locuslab/TCN)，并参考[NVIDIA 在线手势识别研究](https://research.nvidia.com/publication/2016-06_online-detection-and-classification-dynamic-hand-gestures-recurrent-3d)及[连续手势协作装配研究](https://openaccess.thecvf.com/content/ICCV2023W/ACVR/html/Kwolek_Continuous_Hand_Gesture_Recognition_for_Human-Robot_Collaborative_Assembly_ICCVW_2023_paper.html)。这些来源支持使用时序信息，并不证明当前数据足够区分本任务的精细意图。

证据：`intent_data_definition.json`、`intent_baseline_results.json`、`independent_intent_cues.json`。下一项直接工作应继续针对已证实的图像/裁剪敏感性，使用已有 RGB-D 比较静止与主动小角度动作；不能把增加 C 约束、重新采集或训练更大网络当作已经证明必要的修复。

## 继续排查：历史版本、俯仰和横滚串动

用户进一步明确：意图判断必须同时覆盖平移时误转、俯仰时串入横滚/偏航、横滚时串入俯仰/偏航，以及偏航和组合动作，不能只做“平移时冻结姿态”。零位稳定仍是优先项。

用户随后纠正了现象归因：**俯仰时没有报告附带平移，实际不满意的是附带其他姿态变化；横滚与俯仰同样是重点，手掌左右翻转时附带明显俯仰和偏航。** 离线分类器曾把俯仰片段标成“平移”，这是未部署模型的错误输出，不是机器人在录像中出现了额外平移，也不是录像故障的成因。下文分类器评估必须与实际故障区分。

本轮核对对象明确为：1:23–1:26、1:43–1:47、5:08–5:12、5:14–5:20 的平移附带旋转；2:33–2:43、5:00–5:04 的俯仰附带其他旋转，以 2:49–2:51 为较好对照；3:04、3:20、3:40、5:04–5:06 的小指侧翻转附带俯仰/向右偏航，以及 3:49 的拇指侧翻转附带向左偏航。优先沿原始视觉姿态、映射后的目标姿态、实际末端姿态逐层查找串动，而不能把未接入控制的意图模型当作原因。旋转段的修复不以抑制平移通道为目标。

读取用户指定的 9 月 9 日较好版本备份 `before_wrist_recovery_20260909T174835/source_and_config.tar.gz`，其中横滚增益为 1，目前为 3。在最新 C 片段中只反事实地将该增益改回 1，其余输入及处理不变，目标转动峰值从 4.460°变成 1.520°。这说明增益增大会放大已有测量波动，不能据此归因所有跨版本差异；本次没有降低用户要求保留的 3 倍增益。另一个中间版本曾有 C 专用初始保持，当前没有启用该策略。

### 接入原则及当前实际修改

最终应使用平移、俯仰、横滚、偏航各分量的意图可信度，允许组合动作，并有“不确定”输出；不能要求每一帧必选一个轴。输入包含连续图像/深度变化和 HaMeR 当前位姿、近期变化。网络可选因果 TCN 或其他只使用历史帧的模型；“因果”在这里不代表能直接读取人的主观意图。[TCN 官方实现](https://github.com/locuslab/TCN)和提供在线手势实现的[TSM 官方项目](https://github.com/mit-han-lab/temporal-shift-module)是方法参考，不是本工程可用性的证明。

抑制必须针对新出现的非期望分量。已经主动偏航后再平移，要保持已到达的姿态，不能把绝对姿态乘零后转回 C。必须另外验证返回 C 的对应关系、组合动作保留及切换时的连续性。低可信度时不应强制冻结真实运动。

本轮运行代码只补充保存检测器**已经计算出的 21 个二维图像点**，供上述独立时序判断使用，没有增加模型推理次数。原控制器、映射、C 和默认姿态滤波行为未变；未部署有副作用的图像平滑或会吞动作的分类器。**零位抖动及完整意图辅助控制仍未修复完成**。下一次直接工作应首先针对 5:00 这类误判，核对动作起止与有用图像线索，再检验带不确定输出的分量判断，不能继续只追求分类总分或静止段转角下降。

新增证据：`observed_intent_baseline_results.json`、`simple_temporal_intent_baseline.json`、`observed_simple_temporal_intent_baseline.json`、`temporal_command_retention.json`。所有原始录像、旧版恢复入口及之前的独立抑噪试验均保留。

## 本轮：同时保留多个转轴的试验，以及未上线的原因

用户明确要求同时平移、俯仰、横滚、偏航仍可执行，压低的是不期望的耦合。**“每帧选一个动作类别，再关闭其他自由度”不符合这一目标。** 本轮没有将任何这类分类器接入控制，也没有增加按 C 的冻结时间或新接受条件。

### 图像证据不能直接变成角度否决

利用 C 帧的真实深度建立掌部特征点，再在后续 RGB 中跟踪这些点，检查当前姿态是否能解释图像变化。拟合允许自由平移，三个转轴同时存在；机器人位置通道不参与修改。

最初将图像对转动的支持程度直接乘在完整转动向量上。同一 C 静止段的 Gazebo 实际末端峰值从 **3.178°降到0.115°**。但反向检查发现：在原始掌部图像上构造已知的微小转动，0.5°的出平面转动也可能被压到约0.008°或0.049°。该检查使用与重投影一致的平面深度，是可控图像试验，不是真人或 IMU 真值。它足以表明“静止变稳”不能证明正常微动被保留。

原因是小掌部图像中的弱转动证据与深度/特征跟踪误差会混淆。**看不清转动不能被当成没有转动。该直接角度缩放方式已拒绝上线。** 3.178°到0.115°属于失败候选的局部表现，不能作为修复结论。

随后只让图像支持程度改变测量更新速度，始终保留完整目标转角，允许多个转轴一起运动。已知0.5°、5°及三轴组合转动保持后均能到达原转角。但同一 C 段 Gazebo 峰值只从 **3.139°降到2.377°**；0.5°的受控图像慢转检查中，到达最终角度90%的时刻约在输入开始后1.06–1.12秒，而输入斜坡约0.6秒结束。这个时刻包含输入斜坡，不能全部写成算法延迟。它仍暴露了微调跟手性的代价。

上述 Gazebo 测试按原静止段采样间隔回放，并额外保持最后一帧0.65秒；未启动真实相机或进行抓取。已知5°手部输入在控制器中仍映射为15°目标，实际约14.95°；这一项单独检查映射，不能代替图像链的小角度检查。位置指令始终一致。后续标注俯仰、横滚中的系统性串动没有被这些试验证明已修正。

**最终决定：这两个版本均不作为推荐运行版。新试验入口和集成改动已从正式运行代码撤下，原运行行为保留。** 离线试验代码及记录保存在本次数据的 `analysis_feedback`，状态为未部署；没有新版本命令需要用户切换，也没有启动新的真人采集。

证据：`c_model_image_consistency.json`、`image_support_actual_arm.json`（直接缩角的失败候选）、`known_planar_image_rotation_preservation.json`、`image_weighted_temporal_actual_arm.json`、`weighted_temporal_known_motion.json`、`image_motion_trial_status.json`。`image_motion_support_trial.py` 是仅供复现的时间加权试验，不在实时路径中。重新按 C 时保存同帧输入与输出基准的检查也在该离线试验中完成，不能写成原运行版存在了一个新 C 错误并已修复。

### 腕口几何是否是本段零位波动的主要来源

同一静止段相对 C 帧的原始腕口转角峰值约3.774°，HaMeR `global_orient` 参数的转角峰值约3.759°；逐帧变化也基本一致。这比较的是总转角大小，未把不同坐标约定的原始矩阵直接相减。说明主要波动已经存在于模型的整体姿态参数中，单独替换腕口参考点不能解决本段问题。

本轮仍未完成零位稳定和多自由度耦合修复。可观察目标不变：静止时稳定、明确单一转动时减少其他转轴的误动、组合动作中保留用户同时需要的分量。后续候选必须同时通过这三类检查；不能用更重平滑或互斥分类取得其中一项后就上线。

最后针对已确认的裁剪敏感性，保持 RGB 不变，用中心及上下左右各偏1像素的五个裁剪分别推理，再平均旋转。原始静止段转角峰值仅从3.774°降至3.391°，五次推理合计中位耗时约129毫秒、P95约143毫秒（不是完整遥操作延迟）。改善不足以支持增加这项在线计算，未部署。证据为 `c_crop_ensemble_probe.json`。
