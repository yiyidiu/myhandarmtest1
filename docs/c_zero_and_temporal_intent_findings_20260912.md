# 9月12日：按 C 后的转动从哪里来

目标是手保持不动时末端也保持稳定，平移与主动转动均能准确传递。当前只证明了下述原因和局部改善，**没有完成零位稳定及精细控制验收**。

输入为 `hand_motion_observation_20260912T145617_iJYZ`，录制版本为 `2a672ae1a7803c3b455092e052cb15b825defef3`。本次没有重新采集真人动作，没有使用 IMU 驱动机器人，也没有进行抓取验收。所有诊断数据位于该录制目录的 `analysis_feedback`。

## C 与后续停手的直接对照

用户指出“按 C 后手不动会转，后续停手却比较稳定”。只报告测量噪声或滤波减半，不足以解释这个区别。因此，用完全相同的已记录输入比较两种控制状态。

在独立、无物体的 Gazebo 中，保留录制版控制、映射比例和机械臂初始位姿：

| 输入及控制状态 | 末端相对该次机器人零位的最大总转角 | 最大目标转角 |
|---|---:|---:|
| 刚建立 C，输入录制的静止段 | 3.163° | 4.460° |
| 先输入 5°手部转动、返回并停稳，不重新按 C，再输入完全相同静止段 | 3.109° | 4.460° |
| 重新建立 C，输入数值始终完全不变 | 0.000151° | 小于 0.000001° |

静止段使用录像 70.560–72.4 秒的原始已发布位置和姿态，保持原采样间隔；最后额外保持末帧 0.65 秒观察机械臂响应，所以表中峰值不是原录像同时间窗的峰值。返回后第二次试验开始时仍有约 0.049°残差。该对照限定于这一段及这一初始状态，不能外推为所有 C 路径都不可能出错。

**结论：本次复现没有发现 C 初始化额外放大运动；同一段测量波动在返回停稳后依然会驱动机械臂。** 按 C 的第一帧目标与机器人零位一致，额外目标出现在随后变化的测量中。恒定输入对照也没有复现初始化跳转。

原录像 70.560–72.36 秒，已发布手部姿态相对首帧最大变化 2.440°，目标最大变化 4.460°，实际末端最大变化约 2.583°。后续 124–125.8 秒附近停手片段，实际末端相对片段首帧仍有约 2.256°变化。两个真人片段的姿态和运动历史不同，后者只是辅助观察，不能代替上面的相同输入对照。

因此，不把“人手没动”改写成“人手一定转了”；问题是视觉输出会变化，控制器把变化当成了动作。也不能据此断言用户过去每一次 C 异常都是同一原因。

证据：`control_comparison_signals.json`、`stationary_comparison_statistics.json`、`replay_c_state_contrast.py`、`c_state_contrast_actual_arm.json`。原始第五关节反馈在 C 前为 90.000°，本次没有改机械臂初始关节角。

## 已确定的一个测量原因

将 **同一张原始 RGB 图像保持不变**，只改为静止段里实际出现的裁剪框，HaMeR 原始姿态仍变化约 1.784°。这是裁剪影响姿态估计的直接证据，与真实手部转动无关。

使用实际连续图像时，原裁剪的原始姿态变化峰值为 3.774°；诊断性地固定裁剪框后仍有 2.962°。所以裁剪是一个原因，尚不足以解释全部波动。固定裁剪只用于这个因果对照，没有部署成手部移动约束。真实 RGB-D 的简单掌部方向估计也有明显噪声，不能把它当成精确真值；目前不能认定提高分辨率一定解决剩余问题。

证据：`probe_c_crop.py`、`c_crop_probe.json`、`c_rgbd/manifest.json`。RGB 与深度按各自时间戳核对，不以回放 seek 后的首张深度直接配对。

## 保存的抑噪试验及限制

新增的姿态滤波试验只在显式启用 `TELEOP_PRECISE_ORIENTATION=true` 时生效。利用最近观测转向是否一致，减少来回波动触发快速响应的情况；没有新增 C 专用冻结、死区或移动零点，没有更改手部 5°到机械臂 15°的原有映射。

同一静止段的 Gazebo 回放，实际末端最大转动约 3.165°降至 1.580°。固定 5°输入的最终目标仍为 15°，实际约 14.95°。这只是局部改善：残余转动依然存在，慢动作的动态延迟仍需考虑，不能称为已解决。较慢滤波在整段离线回放中还增加了 C 前四帧的姿态拒绝，需在扩大使用前处理；该记录 C 后未增加拒绝不等于所有动作都不会增加拒绝。

`run_precision_hand_observation.sh` 是独立试验入口，会关闭上一版 RGB-D 经验修正，**不是对上一版的全面替代**。关闭该修正在此前左移片段会失去部分误转补偿。普通入口默认行为保持原样；不得仅因静止段改善就推荐整体切换。原生分辨率参数已提供可选项，1280×720 只核对了设备支持，未完成真人精度及运行延迟对照。

证据：`c_noise_actual_arm.json`、`orientation_noise_candidate_summary.json`。原有回退入口仍为 `.runtime/version_backups/imu_guided_pose_trial_20260912/restore.sh`，恢复到本次录制使用的版本。

## 连续帧意图识别的实际结果

按用户标注，将较早整段录像用于训练、另一整段用于选择训练轮次，最新整段作测试，没有随机混合相邻帧。比较逐帧分类器与只看当前和历史帧的时序卷积网络。这里“因果”仅表示不使用未来帧，不表示因果推断或能够直接观测人的意图。

时序网络在最新录像已标注帧上的分类准确率约 53.4%，其中用户认为效果良好的 2:49–2:51 主动俯仰段，24 个评价时刻有 23 个被判为平移。**没有接入控制**，否则会压制用户明确需要的主动转动。这些帧不是独立实验样本，不能据此宣称人群泛化性能。IMU 存在接收时间异常，本次没有将接收时刻直接当作传感器真实采样时刻进行逐轴真值拟合。

方法依据为作者的 [TCN 论文](https://arxiv.org/abs/1803.01271)及[官方实现](https://github.com/locuslab/TCN)，并参考[NVIDIA 在线手势识别研究](https://research.nvidia.com/publication/2016-06_online-detection-and-classification-dynamic-hand-gestures-recurrent-3d)及[连续手势协作装配研究](https://openaccess.thecvf.com/content/ICCV2023W/ACVR/html/Kwolek_Continuous_Hand_Gesture_Recognition_for_Human-Robot_Collaborative_Assembly_ICCVW_2023_paper.html)。这些来源支持使用时序信息，并不证明当前数据足够区分本任务的精细意图。

证据：`intent_data_definition.json`、`intent_baseline_results.json`、`independent_intent_cues.json`。下一项直接工作应继续针对已证实的图像/裁剪敏感性，使用已有 RGB-D 比较静止与主动小角度动作；不能把增加 C 约束、重新采集或训练更大网络当作已经证明必要的修复。
