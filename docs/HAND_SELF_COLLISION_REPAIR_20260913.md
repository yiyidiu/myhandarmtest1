# 张手导致机械臂永久急停：原因与修复

本次录像为 `.runtime/teleop_feedback_20260913T205659_IkL0`，运行版本 `fa2bfa6`。

## 直接原因

原录像约 **3:42.92**，预测已经报告 `f1link2` 与机械臂 `link_2` 将发生自碰撞。
当时程序只拦住六轴机械臂速度，三指手的张开轨迹却已直接发给执行端，继续运行。
约 **3:43.15**，完整机器人状态检查检测到同一对部件相交，锁存急停；后面的
手部输入因此不能再驱动机械臂。预警比锁存提前约 **229 ms**。

这是两个执行端的安全处理不完整。解除锁存、忽略这对碰撞或增大超时都不能解决它。
上一轮机械臂连续性对照将手指固定张开，没有覆盖这次闭合后近身张开的触发条件。

## 实际修改

- 当前Gazebo约束控制入口的手指目标先送到安全检查，再发给手指执行端。
  复用已有的短期完整手臂运动预测，包含机械臂已承诺的运动和手指目标。
- 对已在执行、随后变得危险的手指动作，先检查停止机械臂后手指是否仍会导致
  自碰撞。只有暂停手指能解除该风险时才取消其继续运动，并重查机械臂能否退回。
  仅机械臂方向受限时保留原握持目标，避免无故撤掉预紧指令。
- 暂停手指时替换掉旧的张开轨迹，冻结安全保持目标；不让旧轨迹继续运行。
  空间恢复后后续正常手指请求自动通过，不重设C零位。
- 防止回读本节点自己的旧输出、将已确认的手指目标倒退为旧目标。
- 增加明确的手指空间限制提示，并记录请求、检查后命令和拒绝原因。

机械臂的初始姿态、C映射、增益、滤波、关节限位、碰撞几何和场景没有修改。
新增手指检查不禁止正常抓取目标接触；原机械臂地面/台面保护保留。
真实自碰撞的急停锁存仍然保留。
